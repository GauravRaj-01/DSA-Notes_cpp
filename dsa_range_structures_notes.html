Segment Tree

Range queries (sum/min/max) aur point/range updates efficiently karo — O(log n) per operation.

O(n) build O(log n) query O(log n) update Lazy Propagation
🌲
What is a Segment Tree?
🇬🇧 English
A Segment Tree is a binary tree where each node stores information about a segment (range) of the array. The root covers the entire array, and each leaf covers a single element. Internal nodes store aggregated values (sum, min, max) of their range.

For array of size n: tree has at most 4n nodes (stored as array, tree[1] = root, tree[2i] = left child, tree[2i+1] = right child).
🇮🇳 Hinglish
Segment Tree ek binary tree hai jisme har node ek range (segment) ke baare mein information store karta hai. Root poori array cover karta hai, leaves individual elements cover karte hain. Internal nodes apni range ka sum/min/max store karte hain.

n size array ke liye: 4n nodes ka array banao (1-indexed). tree[1] = root, tree[2i] = left child, tree[2i+1] = right child. Array ki tarah store hota hai!
arr = [1, 3, 5, 7, 9, 11] — Sum Segment Tree
Root = sum of entire array = 36. Each node = sum of its range. Leaves = individual elements.
Build — O(n)
🔨
Building the Segment Tree
🇮🇳 Hinglish
Recursively build karo — pehle left aur right children build karo (bottom-up), phir current node = left child + right child. Leaf nodes pe array value store karo. 4*n size ka tree array lena — safe rehta hai!
🔵 C++ · Segment Tree — Build
const int MAXN = 100005;
int tree[4 * MAXN]; // 4*n size lena hamesha!

// node = current node index (1-indexed)
// start, end = is node ki array range
// arr = original array
void build(int node, int start, int end, int arr[]) {
    if (start == end) {
        // Leaf node — direct array value rakho
        tree[node] = arr[start];
        return;
    }
    int mid = (start + end) / 2;
    build(2*node,   start, mid,   arr); // left child build karo
    build(2*node+1, mid+1, end, arr); // right child build karo
    tree[node] = tree[2*node] + tree[2*node+1]; // dono ka sum
}

// Call: build(1, 0, n-1, arr);
💡 build(1, 0, n-1, arr) se start karo. Node 1 = root. Left child = 2*node, Right child = 2*node+1. Yeh pattern hamesha same rehta hai!
Range Query — O(log n)
🔍
Range Sum Query
🇬🇧 English
Three cases at each node:
1. No overlap: node range is completely outside query range → return 0
2. Complete overlap: node range is completely inside query range → return node value
3. Partial overlap: recurse on both children, combine results
🇮🇳 Hinglish
Har node pe 3 cases:

2. Poora overlap: node ki range query ke andar → directly tree[node] return karo
3. Partial overlap: dono children pe recurse karo, results combine karo

🔵 C++ · Range Query
// l, r = query range. start, end = node ka range
int query(int node, int start, int end, int l, int r) {
    // Case 1: No overlap — node range bahar hai
    if (r < start || end < l) return 0;

    // Case 2: Complete overlap — node range andar hai
    if (l <= start && end <= r) return tree[node];

    // Case 3: Partial overlap — dono children pe jao
    int mid = (start + end) / 2;
    int leftSum  = query(2*node,   start, mid,   l, r);
    int rightSum = query(2*node+1, mid+1, end, l, r);
    return leftSum + rightSum;
}

// Range Min Query (bas + ko min se replace karo!)
// Case 1: return INT_MAX (identity for min)
// Case 2: return tree[node]
// Case 3: return min(leftMin, rightMin)
int queryMin(int node, int start, int end, int l, int r) {
    if (r < start || end < l) return INT_MAX;
    if (l <= start && end <= r) return tree[node];
    int mid = (start + end) / 2;
    return min(queryMin(2*node, start, mid, l, r),
               queryMin(2*node+1, mid+1, end, l, r));
}
💡 Teen cases yaad rakho: Bahar → 0 return. Andar → directly return. Partial → dono children recurse. Sum ke liye 0, Min ke liye INT_MAX, Max ke liye INT_MIN!
Point Update — O(log n)
✏️
Update Single Element
🇮🇳 Hinglish
Ek element update karna ho: root se leaf tak jao (O(log n)). Leaf pe value update karo. Wapas aate waqt har internal node ko recalculate karo (dono children ka sum).
Update arr[2] = 10 (was 5). arr=[1,3,5,7,9,11]
node=1 [0,5]
idx=2 is in [0,5] → go left (mid=2, idx≤mid)
go left
node=2 [0,2]
idx=2 is in [0,2] → go right (idx > mid=1)
go right
node=5 [2,2]
start==end==idx → LEAF! tree[5] = 10
update leaf
Backtrack
node=2: tree[2] = tree[4]+tree[5] = 4+10 = 14 (was 9). node=1: tree[1] = tree[2]+tree[3] = 14+27 = 41 (was 36)
✅ Tree updated!
🔵 C++ · Point Update
// idx = update karna hai kis index pe, val = naya value
void update(int node, int start, int end, int idx, int val) {
    if (start == end) {
        // Leaf node mila — value update karo
        tree[node] = val;
        return;
    }
    int mid = (start + end) / 2;
    if (idx <= mid)
        update(2*node,   start, mid,   idx, val); // left mein jao
    else
        update(2*node+1, mid+1, end, idx, val); // right mein jao

    // Wapas aate waqt current node recalculate karo
    tree[node] = tree[2*node] + tree[2*node+1];
}

// Call: update(1, 0, n-1, idx, newVal);
Lazy Propagation — Range Update O(log n)
💤
Lazy Propagation
🇬🇧 English
Problem: Range update (add X to all elements in [l,r]) naively takes O(n log n) — we'd update each element individually.

Lazy solution: Don't update children immediately. Store the pending update in a lazy array. Only propagate to children when you actually need to visit them (during query or further update). This gives O(log n) range updates!
🇮🇳 Hinglish
Problem: Range [l,r] ke saare elements mein X add karna ho — ek ek karke update karna bahut slow hai (O(n log n)).

Lazy solution: Abhi children ko update mat karo! Pending update ek lazy array mein store karo. Jab actually children ko visit karna padega (query ya aur update pe), tabhi propagate karo. Isliye naam "Lazy" — "Kaam baad mein karo!"
Range Update: add 5 to all elements in [1,3]. arr=[1,3,5,7,9,11]
node=1 [0,5]
[1,3] partially overlaps [0,5] → recurse children
partial
node=2 [0,2]
[1,3] partially overlaps [0,2] → recurse. Left child [0,1] partial, right [2,2] complete.
partial
node=5 [2,2]
COMPLETE overlap! tree[5] += 5*1 = 10. lazy[5] += 5 (for future children — but leaf has none)
lazy stored!
node=4 [0,1]
PARTIAL → propagate lazy to children first (pushdown), then recurse. node=9 [1,1] complete → tree[9]+=5=8, lazy[9]+=5
lazy propagated
node=3 [3,5]
[1,3] partially overlaps [3,5] → recurse. node=6 [3,4] partial → node=12 [3,3] complete → tree[12]+=5=12, lazy[12]+=5
lazy stored
Key insight
Children of lazy nodes are NOT updated yet — only updated when visited. This saves O(n) work!
✅ O(log n) done!
🔵 C++ · Segment Tree with Lazy Propagation (Range Add + Range Sum)
long long tree[4*MAXN], lazy[4*MAXN]; // lazy array add karo

// Pending update children pe push karo
void pushdown(int node, int start, int end) {
    if (lazy[node] != 0) {
        int mid = (start + end) / 2;
        int leftLen  = mid - start + 1;
        int rightLen = end - mid;

        // Left child update
        tree[2*node]   += lazy[node] * leftLen;
        lazy[2*node]   += lazy[node];

        // Right child update
        tree[2*node+1] += lazy[node] * rightLen;
        lazy[2*node+1] += lazy[node];

        lazy[node] = 0; // pending clear karo
    }
}

// Range Update: add val to all elements in [l, r]
void rangeUpdate(int node, int start, int end, int l, int r, long long val) {
    if (r < start || end < l) return; // no overlap

    if (l <= start && end <= r) {     // complete overlap — lazy store karo!
        tree[node] += val * (end - start + 1);
        lazy[node] += val;
        return;
    }
    // Partial overlap — pehle pushdown karo, phir recurse
    pushdown(node, start, end);
    int mid = (start + end) / 2;
    rangeUpdate(2*node,   start, mid,   l, r, val);
    rangeUpdate(2*node+1, mid+1, end, l, r, val);
    tree[node] = tree[2*node] + tree[2*node+1];
}

// Range Query with lazy
long long rangeQuery(int node, int start, int end, int l, int r) {
    if (r < start || end < l) return 0;
    if (l <= start && end <= r) return tree[node];
    pushdown(node, start, end); // query se pehle bhi pushdown zaroori!
    int mid = (start + end) / 2;
    return rangeQuery(2*node, start, mid, l, r) +
           rangeQuery(2*node+1, mid+1, end, l, r);
}
⚠️ Lazy propagation mein pushdown tab karo jab partial overlap ho — query aur update dono mein. "Complete overlap mein bas lazy store karo, children mat touch karo!"

Fenwick Tree (Binary Indexed Tree)

Prefix sum queries aur point updates ke liye — Segment Tree se simpler code, same O(log n) complexity.

O(n) build O(log n) query O(log n) update Simpler than Seg Tree
🌿
What is a Fenwick Tree?
🇬🇧 English
A Fenwick Tree (BIT) stores partial sums cleverly using binary representations. Each index i in the BIT array stores the sum of a specific range whose length is determined by the lowest set bit of i (called lowbit = i & (-i)).

Index i stores sum of: arr[i - lowbit(i) + 1 ... i]
Much simpler to code than Segment Tree, but supports only prefix queries by default.
🇮🇳 Hinglish
Fenwick Tree mein har index i ek specific range ka sum store karta hai. Yeh range i ke binary representation mein sabse neeche wale set bit (lowbit = i & (-i)) se determine hoti hai.

Segment tree se code zyada simple hai — sirf 2 functions (update + query). Par sirf prefix sum queries directly support hoti hain. Range query = query(r) - query(l-1).

The lowbit Trick — Core of BIT
⚡
lowbit = i & (-i) — Kya hota hai?
🇬🇧 English
i & (-i) extracts the lowest set bit of i. In two's complement, -i flips all bits and adds 1 — so only the lowest set bit survives the AND.

• Query: subtract lowbit to move to parent — i -= lowbit(i)
• Update: add lowbit to move to next responsible node — i += lowbit(i)
🇮🇳 Hinglish
i & (-i) = i ka sabse neeche wala set bit extract karta hai. Two's complement mein -i sab bits flip karta hai aur 1 add karta hai — sirf lowest bit bachta hai AND mein.

• Query mein: i -= lowbit(i) → parent pe jao (prefix sum collect karo)
• Update mein: i += lowbit(i) → next responsible node pe jao (update propagate karo)
lowbit examples:
i=6 (110)
-6 = ...11111010 (two's complement). 6 & (-6) = 110 & 010 = 010 = 2. So lowbit(6) = 2
lowbit=2
i=4 (100)
-4 = ...11111100. 4 & (-4) = 100 & 100 = 100 = 4. lowbit(4)=4
lowbit=4
i=5 (101)
-5 = ...11111011. 5 & (-5) = 101 & 011 = 001 = 1. lowbit(5)=1
lowbit=1

🔵 C++ · Fenwick Tree — Full Implementation
int bit[MAXN]; // BIT array (1-indexed!)
int n;

// Prefix sum: arr[1..i] ka sum
int query(int i) {
    int ans = 0;
    for (; i > 0; i -= i & (-i))  // i -= lowbit(i)
        ans += bit[i];
    return ans;
}

// Range query: arr[l..r] ka sum
int rangeQuery(int l, int r) {
    return query(r) - query(l - 1);
}

// Point update: arr[i] mein val add karo
void update(int i, int val) {
    for (; i <= n; i += i & (-i))  // i += lowbit(i)
        bit[i] += val;
}

// Build BIT from array (1-indexed)
// Time: O(n log n) simple, O(n) optimal
void build(int arr[], int sz) {
    n = sz;
    for (int i = 1; i <= n; i++)
        update(i, arr[i]);
}

// Complete usage example:
// build(arr, n);
// query(5)       → prefix sum arr[1..5]
// rangeQuery(2,5) → sum arr[2..5]
// update(3, +5)  → arr[3] mein 5 add karo
💡 BIT yaad karne ka trick: Query mein lowbit subtract karo (i -= i&(-i)), Update mein lowbit add karo (i += i&(-i)). Bas itna hai!

🔵 C++ · Count Inversions using BIT
// Count Inversions: pairs (i,j) jahan i<j but arr[i]>arr[j]
int bit2[MAXN] = {0};
int N; // coordinate compressed max value

void upd(int i) { for (; i <= N; i += i&(-i)) bit2[i]++; }
int qry(int i) { int s=0; for (; i>0; i -= i&(-i)) s+=bit2[i]; return s; }

long long countInversions(vector<int>& arr) {
    // Coordinate compress karo (values ko 1..N range mein laao)
    vector<int> sorted = arr;
    sort(sorted.begin(), sorted.end());
    sorted.erase(unique(sorted.begin(), sorted.end()), sorted.end());
    N = sorted.size();

    long long inversions = 0;
    for (int i = arr.size()-1; i >= 0; i--) {
        // Compressed index
        int idx = lower_bound(sorted.begin(), sorted.end(), arr[i]) - sorted.begin() + 1;
        // Kitne elements arr[i] se chhote hain aur right mein hain
        inversions += qry(idx - 1);
        upd(idx);
    }
    return inversions;
}

Decision Guide — Kab kya use karein?
✅ Fenwick Tree (BIT) use karo jab: • Sirf prefix sum queries chahiye
• Point updates hain
• Code simple rakhna ho
• Count inversions / order statistics
• Sum ya XOR operations (invertible)
✅ Segment Tree use karo jab: • Range min/max queries chahiye
• Range updates chahiye (lazy)
• Non-invertible operations (min, max, gcd)
• Complex queries needed
• Maximum flexibility chahiye
