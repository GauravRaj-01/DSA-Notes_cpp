⚡ Greedy — Basics

Greedy = har step pe locally best choice lo, aur hope karo ki globally optimal answer milega. Sorting + one pass magic!

Locally Optimal Sort First O(n log n) typical No backtracking
⚡
Greedy kya hota hai?
🇬🇧 English
A Greedy Algorithm makes the locally optimal choice at each step, without reconsidering past decisions.

It works when:
1. Greedy Choice Property — local best leads to global best.
2. Optimal Substructure — optimal solution built from optimal sub-solutions.

Classic flow: Sort by some criterion → Iterate and greedily pick → Done in O(n log n).
🇮🇳 Hinglish
Greedy Algorithm har step pe jo abhi best lagta hai woh choose karta hai — peeche nahi dekhta, aage ka sochta nahi.

Kab kaam karta hai:
1. Greedy Choice Property — local best = global best.
2. Optimal Substructure — bade problem ka best answer chhote problems ke best answers se banta hai.

Typical flow: Sort karo → Iterate karke greedy pick karo → O(n log n) done!
💡 Greedy proof trick: "Exchange argument" — assume greedy choice galat hai, phir prove karo ki koi bhi swap se answer better nahi ho sakta. Yahi greedy ki correctness prove karta hai.
Greedy vs DP — Kab kya use karein?
⚖️
Greedy vs Dynamic Programming
🇬🇧 English
Greedy: One pass, no going back. Each choice is final. Works when greedy choice property holds.
DP: Tries all choices, keeps best. Needed when greedy fails (e.g., 0/1 Knapsack).

Rule of thumb: Try greedy first (O(n log n)). If it fails on edge cases → switch to DP.
🇮🇳 Hinglish
Greedy: Ek baar ka decision, wापस nahi. Greedy choice property honi chahiye.
DP: Sab choices try karta hai, best rakhta hai. Jab greedy fail ho (jaise 0/1 Knapsack).

Rule: Pehle greedy try karo (O(n log n)). Edge cases mein fail kare toh DP ki taraf jao.
Greedy works ✅ Activity Selection, Coin change (canonical coins), Huffman, Fractional Knapsack, MST (Kruskal/Prim)
Greedy fails ❌ → use DP 0/1 Knapsack, Longest Path, Coin change (arbitrary coins), Edit Distance, Matrix Chain
⚠️ Classic trap: Coin change with coins=[1,3,4], amount=6 → Greedy gives 3+3=2 coins ✅. But coins=[1,3,4], amount=6 edge: 3+3 vs 4+1+1 — greedy gives 4+1+1=3 coins, DP gives 3+3=2 coins. Always verify with examples!
General Greedy Template
📋
Greedy Problem Solving Template
🔵 C++ · Greedy General Template
// ══ GREEDY TEMPLATE ══
// Step 1: Identify greedy criterion (what to sort by)
// Step 2: Sort by that criterion
// Step 3: Iterate and greedily select
// Step 4: Track result

// Example: Activity Selection (sort by end time)
int greedyTemplate(vector<pair<int,int>>& intervals) {
    // Step 1 & 2: Sort by end time
    sort(intervals.begin(), intervals.end(),
         [](auto& a, auto& b){ return a.second < b.second; });

    int count = 0, lastEnd = INT_MIN;
    // Step 3 & 4: Greedily pick non-overlapping
    for (auto& [s, e] : intervals) {
        if (s >= lastEnd) {      // doesn't overlap
            count++;
            lastEnd = e;          // update last selected end
        }
    }
    return count;
}
💡 Sort criterion decides everything in Greedy. Wrong sort = wrong answer. Always ask: "Sort by start? End? Duration? Ratio? Deadline?" — the problem tells you if you read carefully.

📅 Interval Greedy

Intervals/meetings sort karo by end time → greedy select karo. Activity Selection, Non-overlapping, Minimum Removals — sab same trick!

Sort by End Time Non-overlapping O(n log n)
Problem 1 — Activity Selection
🎯
Activity Selection ProblemClassic
🇬🇧 Intuition
Given n activities with [start, end] times. Select max number of non-overlapping activities.
Greedy insight: Always pick the activity that ends earliest — it leaves max time for future activities.
Algorithm:
1. Sort by end time.
2. Pick activity if its start ≥ last selected end.
🇮🇳 Hinglish
n activities hain [start, end] times ke saath. Max non-overlapping activities select karo.
Greedy insight: Hamesha woh activity lo jo sabse pehle khatam hoti hai — future ke liye zyada time bachega.
Algorithm:
1. End time se sort karo.
2. Activity lo agar uska start ≥ last selected activity ka end.
🔵 C++ · Activity Selection
int activitySelection(vector<pair<int,int>>& acts) {
    // Sort by end time — KEY greedy decision
    sort(acts.begin(), acts.end(),
         [](auto& a, auto& b){ return a.second < b.second; });

    int count = 1, lastEnd = acts[0].second;
    for (int i = 1; i < acts.size(); i++) {
        if (acts[i].first >= lastEnd) {  // no overlap
            count++;
            lastEnd = acts[i].second;
        }
    }
    return count;
}

Problem 2 — Non-overlapping Intervals
✂️
Non-overlapping IntervalsLeetCode 435
🇬🇧 Intuition
Find minimum number of intervals to remove so remaining are non-overlapping.
Insight: Max intervals we can KEEP = Activity Selection answer.
So: min removals = n − max non-overlapping.
Sort by end time, greedily keep, count removals.
🇮🇳 Hinglish
Minimum intervals remove karo taki bache hue non-overlapping hon.
Insight: Max intervals jo RAKH sakte hain = Activity Selection answer.
Toh: min removals = n − max non-overlapping.
End time se sort karo, greedily rakhte jao, removal count karo.
🔵 C++ · Erase Overlap Intervals (LC 435)
int eraseOverlapIntervals(vector<vector<int>>& intervals) {
    sort(intervals.begin(), intervals.end(),
         [](auto& a, auto& b){ return a[1] < b[1]; }); // sort by END

    int kept = 1, lastEnd = intervals[0][1];
    for (int i = 1; i < intervals.size(); i++) {
        if (intervals[i][0] >= lastEnd) {  // can keep
            kept++;
            lastEnd = intervals[i][1];
        }
        // else: overlap → remove this one (don't update lastEnd)
    }
    return intervals.size() - kept;  // total - kept = removed
}

Problem 3 — Minimum Arrow Shots (Minimum Removals variant)
🏹
Minimum Arrow Shots to Burst BalloonsLeetCode 452
🇬🇧 Intuition
Balloons on x-axis as intervals. Each arrow shot at x bursts all balloons covering x. Min arrows to burst all?
Insight: Sort by end. Greedily shoot at the end of first balloon — bursts all overlapping.
Count = number of "groups" = Activity Selection count on same data.
🇮🇳 Hinglish
X-axis par balloons as intervals. Ek arrow x par shoot karo — sab balloons jo x cover karte hain burst ho jaayenge. Min arrows?
Insight: End se sort karo. Pehle balloon ke end par arrow maaro — sab overlapping burst ho jaayenge.
Count = "groups" ki sankhya = same data par Activity Selection count.
🔵 C++ · Minimum Arrows (LC 452)
int findMinArrowShots(vector<vector<int>>& points) {
    sort(points.begin(), points.end(),
         [](auto& a, auto& b){ return a[1] < b[1]; });
    int arrows = 1;
    int shootAt = points[0][1];  // shoot at end of first
    for (int i = 1; i < points.size(); i++) {
        if (points[i][0] > shootAt) { // new group needed
            arrows++;
            shootAt = points[i][1];
        }
    }
    return arrows;
}
💡 Interval Greedy Golden Rule: Jab bhi intervals mein "max select" ya "min remove" ho → Sort by END time + greedy. Yeh ek hi trick hai teen problems mein!
Greedy · Pattern 2 of 5

🗓️ Scheduling Greedy

Jobs/tasks ko deadline aur profit ke basis par schedule karo. EDF (Earliest Deadline First) + Profit sort.

Sort by Deadline Sort by Profit O(n log n) Max Profit
Problem 1 — Job Sequencing with Deadlines
📋
Job Sequencing with DeadlinesClassic / GFG
🇬🇧 Intuition
n jobs, each with deadline[i] and profit[i]. Each job takes 1 unit time. Max profit by scheduling within deadlines?
Greedy: Sort jobs by profit (descending). For each job, assign to latest available slot ≤ deadline.
Use a boolean array of time slots. Greedily fill from right side of deadline.
🇮🇳 Hinglish
n jobs hain, har job ka deadline[i] aur profit[i] hai. Har job 1 unit time leti hai. Max profit?
Greedy: Jobs ko profit ke hisaab se sort karo (descending). Har job ke liye deadline ke andar latest available slot dhundho.
Boolean array of time slots rakho. Deadline ke right se fill karo.
🔵 C++ · Job Sequencing with Deadlines
struct Job { int id, deadline, profit; };

int jobSequencing(vector<Job>& jobs) {
    // Sort by profit descending
    sort(jobs.begin(), jobs.end(),
         [](auto& a, auto& b){ return a.profit > b.profit; });

    int maxD = 0;
    for (auto& j : jobs) maxD = max(maxD, j.deadline);
    vector<bool> slot(maxD+1, false);
    int totalProfit = 0, count = 0;

    for (auto& j : jobs) {
        // Try latest slot from deadline down to 1
        for (int t = j.deadline; t >= 1; t--) {
            if (!slot[t]) {
                slot[t] = true;
                totalProfit += j.profit;
                count++;
                break;
            }
        }
    }
    return totalProfit; // count = jobs done
}

Problem 2 — Task Scheduler (Profit Based)
⏱️
Task SchedulerLeetCode 621
🇬🇧 Intuition
CPU tasks with cooldown n between same tasks. Min time to finish all.
Greedy: Always execute the most frequent remaining task. Use a max-heap + cooldown queue.
Formula shortcut: Let f = max frequency, k = count of tasks with max frequency.
Answer = max(tasks.size(), (f-1)*(n+1) + k).
🇮🇳 Hinglish
CPU tasks hain, same task ke beech n cooldown chahiye. Minimum time mein sab khatam karo.
Greedy: Hamesha sabse zyada baaki wala task execute karo. Max-heap + cooldown queue use karo.
Formula shortcut: f = max frequency, k = f wale tasks ki count.
Answer = max(tasks.size(), (f-1)*(n+1) + k).
🔵 C++ · Task Scheduler (Formula)
int leastInterval(vector<char>& tasks, int n) {
    int freq[26] = {};
    for (char c : tasks) freq[c-'A']++;
    int maxF = *max_element(freq, freq+26);
    int k = count(freq, freq+26, maxF); // tasks with max freq
    return max((int)tasks.size(), (maxF-1)*(n+1) + k);
}

Greedy · Pattern 3 of 5

🏛️ Resource Allocation

Kitne resources (platforms/rooms) chahiye — events/meetings sort karo by start, min-heap se current usage track karo.

Sort by Start Min-Heap (priority_queue) O(n log n)
Problem 1 — Minimum Platforms (Train Station)
🚉
Minimum Platforms RequiredClassic / GFG
🇬🇧 Intuition
Trains arrive at arr[i] and depart at dep[i]. Min platforms so no train waits?
Two-pointer greedy:
1. Sort arrivals and departures separately.
2. Use two pointers: if next arrival < next departure → need new platform.
3. If arrival ≥ departure → a train left, reuse platform.
Track max platforms needed at any time.
🇮🇳 Hinglish
Trains arr[i] par aati hain, dep[i] par jaati hain. Min platforms chahiye?
Two-pointer greedy:
1. Arrivals aur departures alag sort karo.
2. Do pointer: agar next arrival < next departure → nayi platform chahiye.
3. Agar arrival ≥ departure → train chali gayi, platform free.
Har waqt max platforms track karo.
🔵 C++ · Minimum Platforms
int minPlatforms(vector<int>& arr, vector<int>& dep) {
    sort(arr.begin(), arr.end());
    sort(dep.begin(), dep.end());
    int n = arr.size(), platforms = 1, maxP = 1;
    int i = 1, j = 0;
    while (i < n && j < n) {
        if (arr[i] <= dep[j]) { // new train arrives before one departs
            platforms++;
            i++;
        } else {               // a train departed, free platform
            platforms--;
            j++;
        }
        maxP = max(maxP, platforms);
    }
    return maxP;
}

Problem 2 — Meeting Rooms II
🏢
Meeting Rooms IILeetCode 253
🇬🇧 Intuition
Meetings [start, end]. Min rooms so all meetings run simultaneously?
Min-Heap approach:
1. Sort by start time.
2. Min-heap stores end times of ongoing meetings.
3. For each meeting: if heap top (earliest ending) ≤ current start → reuse room (pop + push). Else allocate new room (just push).
Heap size = current rooms in use. Track max.
🇮🇳 Hinglish
Meetings [start, end] hain. Min rooms chahiye?
Min-Heap approach:
1. Start time se sort karo.
2. Min-heap mein ongoing meetings ke end times rakho.
3. Har meeting ke liye: agar heap top (sabse pehle khatam hone wali meeting) ≤ current start → room reuse karo (pop + push). Warna new room (sirf push).
Heap size = abhi use ho rahe rooms. Max track karo.
🔵 C++ · Meeting Rooms II (Min-Heap)
int minMeetingRooms(vector<vector<int>>& meetings) {
    sort(meetings.begin(), meetings.end()); // sort by start
    priority_queue<int, vector<int>, greater<int>> minHeap; // min-heap of end times
    for (auto& m : meetings) {
        if (!minHeap.empty() && minHeap.top() <= m[0])
            minHeap.pop();  // room freed: earliest meeting ended
        minHeap.push(m[1]);  // allocate room, track end time
    }
    return minHeap.size();  // rooms in use = answer
}

Greedy · Pattern 4 of 5

🦘 Jump Game Pattern

Array mein har index pe max jump range di hai. Greedy se farthest reach track karo. Can reach end? Min jumps?

Track maxReach O(n) Single Pass No sorting needed
Problem 1 — Jump Game I (Can Reach?)
🦘
Jump Game ILeetCode 55
🇬🇧 Intuition
nums[i] = max jump from index i. Can you reach last index?
Greedy: Track maxReach = farthest index reachable so far.
At each index i, if i > maxReach → stuck, return false.
Update maxReach = max(maxReach, i + nums[i]).
If maxReach ≥ n-1 at any point → return true.
🇮🇳 Hinglish
nums[i] = index i se max jump. Kya last index tak pahunch sakte hain?
Greedy: maxReach track karo = ab tak sabse door pahunch sakte hain.
Har index i par, agar i > maxReach → stuck, false return karo.
maxReach = max(maxReach, i + nums[i]) update karte raho.
Agar kabhī maxReach ≥ n-1 → true return karo.
🔵 C++ · Jump Game I
bool canJump(vector<int>& nums) {
    int maxReach = 0;
    for (int i = 0; i < nums.size(); i++) {
        if (i > maxReach) return false; // stuck!
        maxReach = max(maxReach, i + nums[i]);
        if (maxReach >= (int)nums.size()-1) return true;
    }
    return true;
}

Problem 2 — Jump Game II (Minimum Jumps)
🚀
Jump Game II — Min JumpsLeetCode 45
🇬🇧 Intuition
Minimum jumps to reach last index (always reachable).
Greedy BFS-like: Think of jumps as "levels". From current level [curStart, curEnd], find the farthest you can reach (nextEnd). When you exhaust current level → jump (jumps++).
Variables: jumps, curEnd (end of current jump's reach), farthest.
🇮🇳 Hinglish
Last index tak minimum jumps mein pahuncho.
Greedy BFS-style: Jumps ko "levels" ki tarah socho. Current level [curStart, curEnd] se maximum door tak pahunch sako (nextEnd). Jab current level khatam ho → jump karo (jumps++).
Variables: jumps, curEnd (current jump ki range ka end), farthest.
🔵 C++ · Jump Game II
int jump(vector<int>& nums) {
    int jumps = 0, curEnd = 0, farthest = 0;
    for (int i = 0; i < (int)nums.size()-1; i++) {
        farthest = max(farthest, i + nums[i]); // best reach from this level
        if (i == curEnd) {  // exhausted current jump's range
            jumps++;
            curEnd = farthest; // jump to farthest reachable
        }
    }
    return jumps;
}

💡 Jump Game pattern summary:
Can reach? → track maxReach, return false if stuck. O(n).
Min jumps? → BFS levels with curEnd + farthest. O(n).
Both are O(n) greedy — no DP needed!
Greedy · Pattern 5 of 5

🌳 Huffman / Merge Cost

Min-Heap se sab karo! Har baar do smallest elements lo, combine karo, wapas daalo. Greedy + Priority Queue.

Min-Heap Combine Smallest O(n log n) Optimal Prefix Code
Huffman Encoding — Greedy Tree Building
🌳
Huffman Encoding
🇬🇧 Intuition
Given character frequencies, build optimal prefix-free encoding (variable length codes).
Greedy: Always merge two least frequent characters. This minimizes total encoding length.
Algorithm:
1. Put all chars in min-heap by frequency.
2. Pop two minimums, merge (cost = sum of their freqs), push merged node back.
3. Repeat until 1 node left = root of Huffman tree.
4. Assign 0/1 along edges to get codes.
🇮🇳 Hinglish
Characters ki frequencies di hain, optimal prefix-free encoding banao (chhoti codes zyada frequent chars ke liye).
Greedy: Hamesha do sabse kam frequent chars ko merge karo. Total encoding length minimize hoti hai.
Algorithm:
1. Sab chars ko min-heap mein daalo frequency ke hisaab se.
2. Do minimum pop karo, merge karo (cost = unki frequencies ka sum), wapas heap mein daalo.
3. Jab tak ek node na bache — woh Huffman tree ka root hai.
4. Edges par 0/1 assign karo → codes milenge.
🔵 C++ · Min Cost of Huffman / Rope Merging
int minCostHuffman(vector<int>& freqs) {
    // min-heap (priority_queue with greater = min on top)
    priority_queue<int, vector<int>, greater<int>> minH(freqs.begin(), freqs.end());
    int totalCost = 0;
    while (minH.size() > 1) {
        int a = minH.top(); minH.pop();  // smallest
        int b = minH.top(); minH.pop();  // 2nd smallest
        int merged = a + b;
        totalCost += merged;              // cost to merge
        minH.push(merged);                // new node back in heap
    }
    return totalCost;
}

Min Cost to Connect Ropes
🪢
Min Cost to Connect RopesClassic / Amazon
🇬🇧 English
Given rope lengths, connect all into one. Cost = sum of two lengths connected each time. Minimize total cost.
Identical to Huffman! Always merge two shortest ropes first. Use min-heap.
If you merge big ropes early, their cost is added multiple times — so merge small first.
🇮🇳 Hinglish
Ropes di hain, sab ko ek mein jodo. Cost = har baar do ropes ki lengths ka sum. Min total cost chahiye.
Bilkul Huffman jaisa hai! Hamesha do sabse chhoti ropes pehle jodo. Min-heap use karo.
Badi ropes pehle join karne par unka cost baar baar add hoga — isliye chhoti pehle!
🔵 C++ · Connect Ropes (same as Huffman)
long long connectRopes(vector<int>& ropes) {
    priority_queue<long long, vector<long long>, greater<long long>> minH(
        ropes.begin(), ropes.end());
    long long cost = 0;
    while (minH.size() > 1) {
        long long a = minH.top(); minH.pop();
        long long b = minH.top(); minH.pop();
        cost += a + b;
        minH.push(a + b);
    }
    return cost;
}
// ropes=[4,3,2,6] → merge 2+3=5(cost 5),
//   then 4+5=9(cost 9), then 6+9=15(cost 15) → total=29
💡 Min-Heap Greedy pattern: "Merge smallest two repeatedly" = always use min-heap. Problems: Connect ropes, Huffman encoding, Stone merging, K-way merge, Kth largest. Template identical — only what you compute changes!

🇬🇧 English
"Max non-overlapping intervals?" → Sort by end time + greedy pick
"Min intervals to remove?" → n − max_non_overlapping (same trick!)
"Maximize profit within deadlines?" → Sort profit↓, try slots from deadline down
"Min rooms/platforms?" → Sort by start + min-heap of end times
"Can reach end / min jumps in array?" → Track maxReach / BFS-level greedy, O(n)
"Repeatedly merge two smallest?" → Min-heap, Huffman/connect-ropes pattern
IntervalSort by END. greedy = pick if start ≥ lastEnd. Non-overlap count = total − kept.
ResourcesSort by START. Min-heap stores end times. Heap size = current rooms. Max = answer.
Merge/HuffmanMin-heap. Pop 2 smallest, merge, push back. Total cost accumulated. O(n log n).
⚠️
Common Greedy Mistakes
⚠️ Wrong sort criterion: Interval problems mein start time se sort karna common mistake hai. End time se sort karo for max non-overlapping / min removals. Start time sort → for resource allocation (rooms/platforms).
⚠️ Greedy vs DP confusion: Coin change with arbitrary coins → Greedy FAILS, DP needed. Fractional knapsack → Greedy works. 0/1 Knapsack → Greedy FAILS. Pehle counterexample check karo!
⚠️ Meeting Rooms I vs II: Meeting Rooms I = kya sab meetings ek room mein ho sakti hain? → Check any overlap (sort + adjacent check). Meeting Rooms II = min rooms? → min-heap approach. Dono alag problems hain!
⚠️ Job Sequencing: Slot assignment mein latest available slot <= deadline se shuru karo (right to left). Left to right karne se suboptimal assignment ho sakta hai.
💡 Greedy verification checklist:
1. Kya sort criterion clearly defined hai?
2. Kya local choice globally optimal hai? (Exchange argument)
3. Ek counterexample banao — greedy fail karta hai kya?
4. Agar fail karta hai → DP ya backtracking use karo.
